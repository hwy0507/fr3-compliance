## “同步标定”已经做了什么，还没做什么

相机用 V4L2 `CLOCK_MONOTONIC` 采集时间，驱动标记为 SOE（曝光开始）；ESN 记录同一主机控制回调入口与状态计算结束时间。双方记录 boot ID，跨重启拒绝配对。离线最近邻配对容差25 ms，策略间隔超过80 ms的缺口不配对，头尾不外推；同时提供当时已经就绪的最新状态索引，便于将来实时显示。

**这是共同主机时间轴上的配对，不是相机曝光到机器人力传感器的物理延迟标定。** 回调时间是主机收到状态的时间，传感器采样、滤波、网络以及驱动延迟尚未独立测量。不要据此声称微秒级同步或精确的撞击响应时间。若要发表延迟指标，需要共同可观测事件/硬件触发及重复实验，估计固定偏移和抖动区间，再单独报告。

神经元还受姿态、速度、轨迹误差等输入驱动；颜色变化不能全部归因于碰撞。输出 a0..a6 是原始模型输出，不能直接当成实际关节力矩或执行位移。无 ESN 对照仍记录模型，但应用减速和让位均为零。

参考：[Linux V4L2 缓冲时间戳](https://www.kernel.org/doc/html/latest/userspace-api/media/v4l/buffer.html)。

## 控制版本和边界

控制器来自本机审核的 `esn_yield_roundtrip_diag_20261124.cpp`，基线 SHA256 `2fda89ec3febab757771df6d7a4c6455d6e93a324bb9e6dc7a28a98a1451d443`。构建只加四处同步插桩，源码与权重完整包含在包内。源文件顶部部分历史注释仍描述旧单程/影子行为，以实际代码、固定启动参数及本说明为准。

- 一次连续 home→pos2→home；pos2处速度到零后立即反向，不重新采集基线。
- 名义速度0.105 rad/s；外力引起的让位速度并不随0.7倍率等比例缩放。
- 运动刚度7轴均300 Nm/rad。normal 关节上阈值 `[40,40,36,36,32,28,24]` Nm，笛卡尔上阈值 `[40,40,40,60,60,60]` N/Nm，保持有限碰撞保护。
- 控制器退出时尝试恢复 `[3000,3000,3000,2500,2500,2000,2000]` Nm/rad；恢复异常被捕获，不能将“尝试恢复”写成读回验证成功。
- 接触门控进入12 N、释放9 N并持续约0.3秒；这是控制逻辑，不替代机器人保护。
- 已存在历史 cartesian_reflex、加速度不连续及力矩边界退出记录。不能把当前包描述为任意撞击都不会退出的控制器，不应提高或绕过保护来获得演示效果。
- 新记录器不增加回调内文件IO/锁/动态分配，但原控制器仍有控制回调内 CSV/控制台输出，实时性能仍需后续优化与测量。
