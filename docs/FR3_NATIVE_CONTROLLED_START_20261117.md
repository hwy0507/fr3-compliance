# 原生笛卡尔阻抗：受控启动、Ready与停止

日期：2026-11-17。交付范围是**源码准备、参数来源核查及离线验证**。本轮没有构造真实Robot、进入机器人控制、操作夹爪、清错或写入机器人参数。网页来源核查只在旁观状态查看，没有接管控制权。

## 1. 原刚度与碰撞阈值来源核查

| 来源 | 核查结论 | 能否作为当前FCI原值 |
|---|---|---|
| 安装版SDK的Robot API及RobotState，官方同版本头文件 | 有阻抗/碰撞阈值setter、接触/碰撞标志，没有这两类数值getter | 不能通过这些接口取得原值 |
| 已保存的Desk任务定义 | 有任务刚度和任务安全参数；缺少本次启动后已应用、未被改写及FCI八数组映射的证据 | 不能 |
| 当前Settings/Safety旁观页面 | 未显示FCI刚度或碰撞阈值数组 | 不能 |
| 安全日志下载 | 工具超时，没有确认取得文件，未声称查到日志内容 | 不能 |
| 本项目源码和既有日志 | 既有位置回放不写这些参数；原生会话只有待授权的刚度事务，没有碰撞setter。不能排除其他客户端、Desk或重启的影响 | 不能反推出原值 |

结论：**来源核查已完成，但当前六维原刚度和有效碰撞八数组仍未核实。**不通过试撞、重启、写默认值或重跑Desk任务来“读取”参数，也不根据一次reflex反算阈值。保持审阅模板为空/false，当前不能启动。

官方依据：[Robot API](https://raw.githubusercontent.com/frankarobotics/libfranka/0.21.3/include/franka/robot.h)、[RobotState](https://raw.githubusercontent.com/frankarobotics/libfranka/0.21.3/include/franka/robot_state.h)。历史任务证据边界见[已有参考点与来源审计](FR3_WRENCH_REFERENCE_FIX_20261115.md)。真实来源审计和历史任务快照仅本地保留，未新增发布真实配置。

后续需要厂家支持的当前配置读回/导出，或可证明属于**当前机器人、当前启动周期、已应答且此后未改写**的配置应用记录。若确实无法取得，应另行提出并授权建立已知配置/结束配置的方案；不能称为“恢复原值”，本轮未建立该替代方案。

## 2. 新入口与默认状态

- `tools/fr3_native/launch.py`：本地JSON审阅检查、执行准备与独立停止请求。`check`只读本地文件；`stop`只写本地STOP文件；只有明确的`execute`分支可能交接到C++。
- `controlled_start.cpp`：完整SDK启动流程。**编译开关FR3_NATIVE_EXECUTION_BUILD默认0**，默认构建遇到执行请求直接拒绝，不构造Robot。执行构建本轮仅编译链接，未走有效执行路径。
- `start_protocol.hpp`：严格清单解析、九项授权、原刚度范围、IP、CPU、会话标识、证据摘要及短时有效期检查。拒绝多余/截断字段、未知模式、未授权轻推与失效清单。
- `operator_gate.hpp`：纯操作者状态及锁存停止逻辑；停止后同一会话不能重新授权接触。
- `REVIEW_TEMPLATE.json`：增加启动字段及来源文件引用，所有授权仍false、原值和来源仍null。不是可执行配置，没有把现有候选接受当成运动/参数写入授权。

原位置回放、VMC/ESN、工具/相机/碰撞参数均未改变。原生候选刚度和保护包络沿用既有提案；未为启动放宽99%/2ms等保护。

## 3. 执行前的检查顺序

1. Python解析JSON时拒绝重复键、NaN和错误类型；九项审阅必须显式true。轻推另需`contact_authorized=true`及施力点/力尺度依据。原刚度必须与来源记录一致。
2. 两份来源记录分别绑定SHA256、机器人IP、当前FCI范围、启动周期与未改写确认。只接受`vendor_current_readback`或`acknowledged_applied_record`类型，不接受历史任务、示例或默认值。碰撞来源须包含lower/upper × torque/force × acceleration/nominal八数组，长度分别7/6，均为正有限数、lower≤upper，并有接触包络审阅。
3. 授权与确认有有效期（最长10分钟），不足30秒拒绝。记录引用只能约束已提供的文件；软件**不能认证其确由厂家产生，也不能代替维护者核实内容和当前性**。本轮没有生成伪造的“已核实”来源文件。
4. 执行准备要求现场交互终端、全新运行目录和一次性会话ID。Python使用`os.execv`直接交接进程，避免Ctrl-C触发Python父进程提前杀掉C++，破坏清理事务。
5. C++在任何Robot构造前再次核对清单，并要求30秒内输入本次精确的`START HOLD <会话ID>`或`START PUSH <会话ID>`。不是Desk的RUN YOUR TASK。目录以LIVE_STARTED独占锁防止复用，已有STOP立即拒绝。
6. 仅控制工作线程绑定指定CPU并由SDK强制实时调度；终端监督线程保持非实时。读取Idle新状态，预热本地模型，重新采1001帧基线并通过原有完整静止判据。旧基线文件不代替此步骤。
7. 锁当前进程内存，重新检查授权有效期和取消标志。随后由原生会话再次核对新鲜状态、完整工具配置、参考连续性、竖直方向、关节界及静态力，再进入已审阅的刚度写入/恢复事务。

这里列出的是**未来单次执行流程**，不是本轮已经实施的动作。即使参考固定，激活控制也可能产生物理动作，必须获得单独授权。

## 4. Ready与接触权限

| 提示 | 含义 |
|---|---|
| NOT_ACTIVE | 尚未处于有效控制状态，禁止接触 |
| SETTLING | 前3秒建立稳定状态，禁止接触 |
| READY_HOLD | 无接触保持稳定；该模式永远不能启用轻推 |
| READY_TO_ARM | 轻推模式稳定，但仍禁止接触；现场需再输入PUSH |
| READY_PUSH | 稳定且收到本次PUSH确认，允许已审阅的有限轻推 |
| CONTACT / RECOVERING | 及时释放；观察原生回位，不再增加推力 |
| STOP_REQUESTED / STOPPED / FINISHED | 接触权限撤销，不重试、不自动回零 |

Ready来自实际保护状态机，不以连接成功或固定等待时间代替。监督线程核对回调心跳，状态超过100ms未更新时撤销Ready并请求停止；无接触保持或尚未启用PUSH时，检测到接触/恢复状态即退出。终端输出、键盘和文件读取都在非实时线程，回调不打印或写文件。

## 5. 停止入口与日志

- **Ctrl-C / SIGTERM**：锁存无锁取消标志，回调检查后通过SDK退出并尝试恢复审阅过的原刚度。
- **STOP+回车、q+回车、空回车或其他非PUSH命令**：请求停止。终端EOF/断开也请求停止。
- **独立终端**：`python tools/fr3_native/launch.py stop RUN_DIRECTORY`，只写该运行目录的STOP文件，由监督线程约20ms轮询。重复停止请求幂等，不启动Robot或接管其他客户端。
- 旧/失效Ready不允许PUSH；停止一经请求，不接受重新启动或重新启用接触。

这些都是软件退出请求，**不是硬件急停确认或物理停止时间保证**。通信完全失效、线程阻塞或断电时，无法保证及时执行取消和刚度恢复；现场停止装置始终必要。不自动清错、不屏蔽碰撞、不杀进程重试。

正常结束、操作者停止、SDK异常都退出控制后尝试恢复原刚度；保持原始控制异常及单独恢复失败。诊断写失败不覆盖原控制异常。记录原始wrench/状态、SDK故障尾部、基线、参数事务结果、回调成本及工作线程缺页增量。回调成本不包含SDK发送和网络往返；软件停止与实际响应仍待真机验收。
