# 2026-11-17 下午：FR3 操作、FCI 柔顺控制准备与失败排查总结

日期：2026-11-17，Asia/Shanghai。本文按会话与本地执行记录整理；没有日志时间的环节不补造具体分钟。

## 1. 目标和当前结论

最终研究目标是在示教轨迹运动中加入**主动恢复 VMC**：末端受外力后允许有限偏离，保持低速和保护，随后逐渐越过接触物并回到任务轨迹。本轮中间目标先降为：在 **EXEC＋FCI** 下，不按 Pilot 的引导按钮，用手小幅拖动末端，松手保持新位置。

**今天完成了位置轨迹重放与慢速返回，也实际进入过原生笛卡尔阻抗保持；没有完成可供持续自由拖动的 FCI 接触验证，更没有完成沿轨迹 VMC/ESN 柔顺实验。** 不能把“软件编译通过”“出现 Ready”“位置重放成功”写成柔顺真机实验成功。

| 项目 | 本轮结果 | 证据边界 |
|---|---|---|
| 先前示教轨迹重放＋慢速回零 | 一轮完整执行成功 | 位置控制；没有加 VMC、没有抓放，也不授权人在重放中推机器人 |

## 2. 实验背景与硬件信息

- FR3，系统镜像5.10.0；此前出现Rescue System启动界面，重启后恢复连接。Rescue是系统启动问题，与后面的软件受力退出分开记录，未证明两者相关。
- 本机测试使用libfranka/pylibfranka 0.21.3、RT内核 `6.12.117-franka1`。具体依赖以执行证据为准。
- 机器人当前读回的总负载配置约 **1.191 kg**；法兰坐标下质心配置约 **[0.010, 0, 0.081] m**。这些是配置值，**实际工具总质量、质心和惯量没有独立核实完成**。
- 工具包含夹爪、金属转接件、相机及支架/线缆。早先照片中的腕部相机被猜测为D435i，未以铭牌或序列号确认。录像检查时USB实际枚举到Orbbec Gemini 335和FHD Camera；这不能反推腕部一定是哪一型号，也不能替代相机外参或工具标定。

- 本轮**确实写入并保留过**候选笛卡尔刚度 `[300,300,800,50,50,50]`。不能写成“整个下午零参数写入”。未改碰撞阈值、负载、质心、惯量或相机标定参数。

## 4. 补齐逐帧日志与参考点处理

`tools/fr3_wrench_trace.hpp` 和位置执行器现在保留逐帧q/dq/q_d、力矩、原始O/K wrench、接触/碰撞/错误、通信率、机器人时间和O_T_EE/EE_T_K。SDK直接抛出ControlException时另存SDK尾部，避免应用回调缺失触发帧。

原有限缓冲保持功能不变；操作者结束的长会话改为预分配有界SPSC队列，实时线程仅复制固定字段，非实时线程落盘。队列满或IO失败会退出，不静默丢帧，不随会话无限增加内存。耗时逐帧记录前64010帧，另有全会话次数、总耗时与最大值。

参考点必须区分：K点力矩旋转到基座轴后，转到EE点还要加 `(p_K-p_EE) × F`。本轮代码以明确K字段构造受力，原O力矩保留作诊断。**不能直接拿O字段力矩减去K点基线**。某些历史记录中的O矩关系也不应推广成所有固件的通用语义；物理施力方向与符号仍需独立验证。

## 5. 为FCI实时通信做过的事

1. 编写只读C++接收/模型转换探针。只读测试不发送控制指令，其接收质量不能代替双向1kHz控制验收。
2. 检查RT内核、内存锁、线程实时优先级、网卡速率/双工和累计错误。控制线程后来绑定CPU21，与观察到的网卡IRQ所在CPU一致；这是实现选择，不是任何机器通用的推荐CPU编号。
3. 用户执行主机EEE禁用，旧脚本报 `advertised` 读回不匹配。核实发现驱动禁用EEE后可能把广告掩码40回报为0，设置可能已生效；修复为在禁用时接受0或原掩码，实际开关/激活/计时器仍严格核对，恢复时仍核对原值。原备份保留，不覆盖或循环重试。
4. ICMP对比：两次各2500包均0丢包，均值约0.143→0.134 ms，最大约1.590→1.030 ms。不能用ping结果证明控制通信已合格或证明EEE是唯一原因。
5. Cheese预览曾占用约一个CPU核以上，按用户授权在试验期间暂停，退出后恢复；没有关闭全部桌面服务。
6. 初期软件99%门槛在少量漏指令后很快退出。依用户要求先后引入95%、90%显式原生候选，另对低速原生参考引入5 ms接收周期候选。默认仍99%/2 ms；未降低SDK自身通信错误保护，未将这些修改扩展到外部力矩VMC/ESN。

SDK成功率是近期控制命令的接收统计，不是“必须逐包100%”，也不是接收状态周期。原生内部伺服仍是机器本地控制，不能用“动作慢”代替通信/停止验证。官方communication_test可能运动和设置阈值，本轮没有把它当作无运动测试运行。

最近一次核实EEE为关闭，原备份仍在本地；本次交接没有重新读取或改动网卡。主机EEE工具固定本机接口/PCI身份，换电脑必须重新审阅；它不是通用一键网络优化工具。本报告不发布MAC、凭据或可复用的真实授权文件。

## 6. 原生阻抗与有限拖动具体做法

### 6.1 两类行为

- **定点阻抗**：先固定实际首帧q_d参考，选择厂家 `kCartesianImpedance`。无外力时希望保持启用姿态；非零刚度意味着受推后倾向返回参考。没有主动回零或示教轨迹目标。
- **有限随动**：在独立DRAG启用后，检测普通contact或相对静态基线新增力超过1 N，参考缓慢跟随实测关节姿态；释放界0.5 N，松手冻结新参考。采用三重极点−6/s整形，每关节参考速度/加速度/jerk上限0.015 rad/s、0.2 rad/s²、1 rad/s³。

有限随动是本项目包装的参考更新逻辑，不是厂家完整Teach模式。这里只在经过局部限速的随动分支关闭参考低通，SDK rate limiter仍开启。没有与主动恢复VMC/ESN叠加。

### 6.2 当前候选边界

| 项目 | 数值/行为 | 含义 |
|---|---|---|
| 笛卡尔K | [300,300,800,50,50,50] | K轴；平移N/m、转动N·m/rad |
| 启动静态资格 | ≥0.9秒/900帧，入口采1001帧 | Idle、稳定、无错误/contact/collision等 |
| 启动绝对力/矩 | 2 N / 1 N·m | 自加工程门槛，不是厂家报错阈值 |
| 建立保持 | 前3秒不接触 | 通过后才有Ready资格 |
| 运行绝对力/矩 | 6 N / 1.5 N·m | K、EE两点各自检查；不减基线 |

| 相对力矩变化 | 默认0.25；单独0.5、1 N·m候选 | 需专用清单/审阅，未把全局默认改成1 |
| 实测TCP线/角速度退出线 | 0.05 m/s / 0.2 rad/s | 检测退出界，不是认证硬限速 |

相对力矩是 `||M−M₀||`，绝对力矩是 `||M||`；两者独立。即使相对候选为1 N·m，仍可能先达到绝对1.5 N·m，不表示额外保证能施加1 N·m。

### 6.3 刚度保留、Ready与操作者结束

原始“恢复原值”分支要求核实原刚度；用户后来明确选择**保留试验刚度**，新增独立RetainTrial，只在资格通过后设置一次，结束不把未知原值写回。数值原刚度/碰撞来源仍保持unknown，不能用全true旧表冒充已核实。

原15秒/2秒轻推窗口不适合用户持续拖动，且工具确认延迟曾导致Ready后尚未启用就到期。后来新增operator-ended：由操作者结束，不再按15/60秒或2秒接触倒计时退出；非倒计时保护全保留。还修正了终端遗留的“2秒内松手”旧文字。

Ready分级：`SETTLING` → `READY_TO_DRAG` → 另行输入DRAG后才有 `READY_DRAG`。实际控制未启用、状态过期、接触未授权或STOP锁存时不发可上手提示。默认构建关闭真实执行，清单/一次性口令/新目录锁均保留。

### 7.1 “刚一上手就退出”是什么

最后一帧按K点及其静态基线重算：新增力约 **1.0285 N**，新增力矩 **0.251300 N·m**，超过0.25线；绝对力约1.1642 N、绝对K点矩约0.6745 N·m。该帧通信成功率1.0，SDK碰撞/通信错误标志为0，SDK ControlException也未触发。

因此这是**我们软件的相对力矩保护先退出**，并非证明没有进入原生阻抗，也不能写成通信导致的厂家红灯。它同时说明当时把短时轻推包络用于自由拖动不匹配需求。未完成释放后保持验证，不能从出现 `READY_DRAG` 推导为功能通过。

该约130秒会话逐帧队列无溢出/积压，回调观测最大约291.7 μs；单次观测不是最坏执行时间证明。录像请求期间相机探测失败与退出在时间上接近，退出原因不能改写为“摄像头造成通信故障”。

### 7.2 为什么1 N·m新版仍没进入控制

在用户指定1 N·m**相对变化**候选后，进行了新的完整静态资格读取：

| 项目 | 数值 |
|---|---:|
| 采样 | 1001帧，约1.001秒 |
| 静态K力均值/最大 | 1.9067 / 1.9911 N |
| 静态K力矩均值/最大 | 1.000398 / 1.036235 N·m |
| 超过启动1 N·m的帧数 | 508 |
| 刚度写入尝试/控制进入 | 0 / 0 |

用户确认当时空夹爪、完全撤手、无接触、线缆无牵拉。失败原因是 `absolute baseline above startup bound`。这是原有**启动本底门槛**，与之后运行时相对力矩变化1 N·m不同。

该1 N·m启动门槛是本项目自加工程限制，轻微超过本身不能证明机器人危险，也不能证明可以忽略。当前只能确认静止估计残差，不能唯一归因于负载、摩擦、传感器或模型；不应直接置零或改门槛后把它当作标定通过。记录后的配置约1.191 kg，关节2静态外力矩残差约0.98 N·m；Jacobian最小奇异值约0.195，单凭这组数据也不能完成质量/质心识别。

这次启动器已载入软件候选，但在写参数/控制之前拒绝，**不存在“1 N·m自由拖动真机验证已通过”**。

## 9. 如何离线复现

基础：C++17、Eigen3、libfranka 0.21.3、Python≥3.10、NumPy和SciPy；先用 `python -c "import numpy, scipy"` 检查当前解释器。编译依赖已安装时，从本仓库根目录运行，输出目录须不存在：

```bash
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 python tools/check_package_offline.py \
  --output /tmp/fr3-afternoon-offline-new-run
```

## 10. 正式柔顺实验前还缺什么

1. **实际工具核实**：称量夹爪/转接件/相机/支架，核对质心、惯量及坐标系来源，确认1.191 kg配置覆盖的具体部件。不能用单一姿态残差直接反算并写入完整参数。
2. **独立受力核对**：确认施力点/方向，用可追溯外力或测力方式核对符号、参考点、静态残差、摩擦/迟滞和不同姿态下的变化。区分模型估计与独立传感器测力，不把扣基线当标定。
3. **当前保护来源**：取得当前有效碰撞/安全配置的可信来源与版本；原值未知继续如实标unknown，不用历史任务、默认值或试撞反推。
4. **冻结一套可解释的接触包络**：按施力位置、允许力/矩和空间，统一启动、运行绝对/相对界；不再每触发一次就顺次抬高。急停是后备，不能替代受控启动、稳定性与停止验证。
5. **小范围接触与释放验收**：先无接触、再有限单方向轻推、释放保持与停止验证；清楚记录哪类保护触发，保留失败，不把Ready当完成。人工拖动与轨迹运动中接触是不同阶段。
6. **完整通信/停止核实**：测试双向控制中的周期、成功率、回调耗时、缺页和停止行为，包括非实时监督/写盘阻塞时的行为；不能把100 ms监督检查当作实际停止时间上界；不以ping、只读包流或平均值作认证。
7. **接入真实任务参考**：原生有限随动通过后，再单独验证主动恢复VMC/ESN与示教轨迹参考、状态/观察器接口；配置变更重新审阅。沿轨迹接触不是把现有位置重放程序允许推一下就完成。

正式项目评价仍应报告任务完成、交互力/矩、速度/空间/机器安全违规和恢复质量；若比较效率，沿用项目冻结的SPT等协议。没有完成任务时，不能只用“力低”“没红灯”判定成功。
